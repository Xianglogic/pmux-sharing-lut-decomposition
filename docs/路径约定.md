# 路径与运行产物

项目文件使用相对路径，外部工具位置通过参数或当前进程的环境提供。脚本根据自身位置定位仓库，不依赖开发者原来的盘符和工作目录。

## 配置方法

- 输入、器件模型、证明模板和随包工具，从项目根目录定位。PowerShell使用PSScriptRoot，Python使用脚本文件的位置。
- Windows验证入口从命令行参数、本机配置、套件环境和PATH依次获取工具位置。配置模板为config/windows-tools.example.psd1，本机文件为config/windows-tools.local.psd1。配置中的相对路径从仓库根目录计算，不受启动时的工作目录影响。
- 本机专用环境文件不提交。文档写清参数和配置方法，不填写某位开发者的安装目录。
- 临时工作目录由系统或-WorkRoot决定。新运行记录写入runs，构建输出写入rebuild，不作为日常源码提交的内容。

## 既有归档

在bff0851提交中，2251个已跟踪文本文件命中了本机路径特征。其中1866个位于历史runs目录，337个位于evidence；当前scripts和proof_templates没有命中。其余命中还包含上游代码中的示例路径。这些文件大多是完整提交包导入时保留的历史记录，其中的路径不一定是当前运行依赖。

原始日志、网表的src属性保持原样。它们与证明输入、测量结果及哈希绑定，批量替换路径会改变原始字节。BUILD.json、BUILD_CONDITIONS.json、CHANGE_SCOPE.json已整理为仓库视图：编译器使用工具名，随包工具使用相对路径，历史输入只保留归档名称；原始记录另存，并在各文件中保留原记录哈希。工具版本、非路径编译选项和已有程序哈希不变。

两份runtime/yosys-config仍是冻结运行目录中的历史构建附属文件。当前Windows运行和重建入口不调用它们，不将其作为可迁移的插件开发SDK使用。

日常仓库维护源码、输入、运行脚本、证明配置、必要结果摘要和哈希。后续完整日志与中间产物单独归档。新增忽略规则不会自动移除已跟踪文件，既有记录仍保留；本次不改写提交包或Git历史。

## 提交前检查

```bash
python scripts/Check-RepositoryPaths.py
python scripts/Check-RepositoryPaths.py --staged
```

检查范围为运行脚本、自研源码副本、证明模板、导航文档、配置模板及整理后的根目录构建记录，发现写死的盘符路径、用户目录或WSL挂载路径时返回非零。原始证据与上游代码不参与此项检查。检查通过表示这些维护入口没有命中规则，不表示历史归档或二进制中完全没有路径。

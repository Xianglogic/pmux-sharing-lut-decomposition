# 配置与复验说明

本说明按2026年11月3日答疑更新。源码、运行程序和十组测量记录保留提交时的版本；复现时区分归档流程与新增要求。

## 工具与路径

普通综合在Windows x64运行，支持Windows PowerShell 5.1或PowerShell 7；效率入口需要PowerShell 7。保留完整runtime目录及两个yosys.exe各自配套的ABC、DLL和share器件库。普通综合不需要另外安装Python、WSL或系统Yosys。

当前两版基于Yosys 0.69，核心提交9f75ca1f9834a39a863915b5dae0c7b1e33533bc，使用MSVC 19.51和相同Release参数，ABC二进制哈希一致。C161、C162明确0.69的具体版本可选，不必迁移到早先列出的dirty构建。重建后的双方仍需统一核心、ABC、编译器和构建参数。

脚本从项目位置解析路径。不要将其他安装目录的ABC或器件库混入运行目录。重新构建写入rebuild目录，冻结的runtime保留。

## 综合入口

两版沿用相同外部脚本和默认参数，目标系列为cycloneiv。读取RTL后执行proc和setundef -init -params -zero，再进入完整synth_intel。两版的初始化、输入参数和网表输出阶段应一致。

C162允许新增优化pass及统一修改ABC脚本；C166要求保留其他原版pass的实现与调用顺序，不得额外多次调用ABC。固定脚本由pmux_abc9_script设置，再调用上游ABC9。NoPost默认流程不执行ABC9后的自研LUT重构，复现时不要手动追加lut4_cone_fold或lut4_window_rewrite。

## 时间与内存

完整墙钟时间覆盖Yosys启动、RTL读取、综合、ABC、网表输出至退出。内存看Yosys主进程的峰值物理工作集。EQY另行运行，不计入综合耗时。两版使用同一计量工具。

C164、C166明确的测量方法为：

1. 关闭杀毒软件并记录环境。
2. 测量开始或系统重启后，只用原版对pmux_case05_nested预热10次。
3. 同一外部脚本逐例运行原版与优化版；耗时或内存任一超过原版5%均需处理。
4. 短用例按答疑要求成对复核5次，分别计算两版均值后再求增幅，保留首次和追加记录。

归档十组测量在会话开始时对九例原版各预热10次，共90次；现有Run9.ps1的Measure模式也沿用这一方法。运行该入口得到的是归档方案的复现结果，与新指定的nested单例预热不同。

现有Measure-current.ps1只在短用例首次耗时超限时追加复核，内存按原始配对逐对检查。归档100对内存全部在5%以内。后续按新规则测量时，还需处理仅内存超限的情形，并保留原归档数据。

## 形式验证环境

包内提供ABC9后中间网表、形式模型、EQY配置和复证脚本。Reprove.py使用Linux/WSL，依赖Python、bash、make及OSS CAD Suite验证工具。--oss-root应指向该环境实际的安装目录。

```bash
python3 scripts/Reprove.py --oss-root /path/to/oss-cad-suite --jobs 2
```

C163、C168说明赛事方应准备并调试OSS CAD Suite，但未保证提供WSL。现场前应确认工具版本、路径及Linux/WSL支持；仅提供Windows安装路径不能直接运行当前Linux入口。综合程序运行在原生Windows，证明平台另行记录。

## 结果与记录

面积主指标仍为全部九例最终LUT＋独立NOT优化率的逐例算术平均；加权逻辑资源和总cells缩减率作为补充。C166说明DFF或IO超过原版20%会影响评分。当前九例DFF均不增加，最终端口名称、方向和位宽一致。

新测量写入独立runs目录，注明预热方法和工具版本，不覆盖十组归档记录。源码、程序或测量方法变化后，另存对应证据，旧记录继续对应原环境。
